🔴 Fix #1 — SQL Injection

Replace string concatenation with a PreparedStatement so SQL structure and data stay separate. Contrast's guidance recommends an ORM (Hibernate) or bound parameters.

❌ Vulnerable — PaymentController.java:55
String q = "SELECT * FROM payments " + "WHERE card = '" + creditCard + "'"; jdbcTemplate.execute(q); // unsafe
✅ Secure
String q = "SELECT * FROM payments WHERE card = ?"; jdbcTemplate.query(q, new Object[]{ creditCard }, rowMapper); // bound param
✅

Best practice

Prefer Spring Data JPA / Hibernate repositories. If raw SQL is unavoidable, always bind parameters — never concatenate untrusted input.

🟡 Fix #2 — Weak Cryptography (MD5)

MD5 is collision-broken. For password storage use an adaptive KDF (bcrypt/Argon2); for general hashing use SHA-256+.

❌ Insecure — Digester.java
MessageDigest md = MessageDigest.getInstance("MD5"); byte[] h = md.digest(pwd); // broken
✅ Secure — bcrypt
BCryptPasswordEncoder enc = new BCryptPasswordEncoder(); String h = enc.encode(pwd); // salted + adaptive
✅

Best practice

bcrypt, scrypt, and Argon2 include per-hash salts and tunable work factors. Reserve SHA-256/SHA-3 for non-password integrity hashing.

🟡 Fix #3 — Reflected XSS

The trackingId parameter is reflected unescaped on /api/shipments/track. Encode output for its HTML context.

❌ Vulnerable
<div>Tracking: <%= trackingId %> // raw reflection </div>
✅ Secure
<div th:text="\${trackingId}"> </div> // Thymeleaf auto-escapes
✅

Best practice

Use a templating engine that auto-escapes (Thymeleaf, FreeMarker). Encode based on context — HTML, attribute, JS, or URL — and validate input at the boundary.
