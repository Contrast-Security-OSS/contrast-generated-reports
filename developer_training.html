SQL Injection

CWE-89 · PaymentController.java
▶

What it is: SQL injection allows attacker-controlled input to alter query structure, enabling unauthorized reads, writes, or destructive actions.

Cargo Cats case: untrusted input is concatenated into a payment query in PaymentController, creating a critical injection path.

Attack scenarios: data breach via OR 1=1, and data destruction via stacked statements like DROP TABLE.

Secure pattern: prepared statements with bound parameters, strict allow-list validation, and least-privilege DB accounts.

Insecure Example 
// PaymentController.java (vulnerable)
String sql = "SELECT * FROM payments WHERE account_id = '" + accountId + "'";
return jdbcTemplate.queryForList(sql);
Secure Example 
// PaymentController.java (fixed)
String sql = "SELECT * FROM payments WHERE account_id = ?";
return jdbcTemplate.queryForList(sql, accountId);

Command Injection

CWE-78 · webhookservice command execution flow
▶

What it is: command injection occurs when user input is passed to a shell command without strict separation of arguments.

Cargo Cats case: attack attempts included reverse-shell payloads, exfiltration commands, and system-impacting shell tokens.

Attack scenarios: remote shell access, reading sensitive files, and service disruption.

Secure pattern: avoid shell invocation; use safe APIs, strict argument allow-lists, and execution context hardening.

Insecure Example 
// WebhookProcessor.java (vulnerable)
String cmd = "curl -X POST " + callbackUrl;
Runtime.getRuntime().exec(cmd);
Secure Example 
// WebhookProcessor.java (fixed)
URI uri = URI.create(callbackUrl);
if (!ALLOWED_HOSTS.contains(uri.getHost())) throw new SecurityException();
HttpRequest req = HttpRequest.newBuilder(uri).POST(HttpRequest.BodyPublishers.noBody()).build();
client.send(req, HttpResponse.BodyHandlers.discarding());

Cross-Site Scripting

CWE-79 · /api/shipments/track
▶

What it is: reflected XSS injects attacker script through request input and reflects it in the response.

Cargo Cats case: the trackingId parameter is rendered without output encoding.

Attack scenarios: session hijacking, phishing overlays, and keylogging payloads in user browsers.

Secure pattern: context-aware output encoding, template auto-escaping, CSP, and HTTPOnly cookies.

Insecure Example 
// ShipmentController.java (vulnerable)
String html = "<h2>Tracking: " + trackingId + "</h2>";
return ResponseEntity.ok(html);
Secure Example 
// ShipmentController.java (fixed)
String safeTrackingId = HtmlUtils.htmlEscape(trackingId);
String html = "<h2>Tracking: " + safeTrackingId + "</h2>";
return ResponseEntity.ok(html);
